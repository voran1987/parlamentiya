# Революционная ситуация — Supabase

С 1 ноября 2026 года игра `/revolyuciya/` использует Supabase вместо Firebase.

## Архитектура

- HTML-сайт остаётся на GitHub Pages.
- Клиент `revolyuciya/supabase-client.js` обращается только к `/functions/v1/revolution-game`.
- В Supabase развернута Edge Function `revolution-game`; её исходник хранится в `supabase/functions/revolution-game/index.ts`.
- Игровые данные хранятся в `public.revolution_game_rooms` (DDL в `revolyuciya/supabase-schema.sql`).
- RLS включён, прямые права на таблицу для `anon` и `authenticated` отозваны. Только серверная функция обращается к таблице с помощью серверного `SUPABASE_SERVICE_ROLE_KEY`. **Этот ключ нельзя помещать в GitHub или клиентский JS.**
- В браузерном коде используется только публичный `sb_publishable_` ключ.

## Синхронизация и авторизация

- При создании комнаты ведущий получает уникальный секретный токен из `crypto.getRandomValues`. Токен сохраняется **только в локальном хранилище того же браузера**, а в Supabase записывается его SHA-256.
- При занятии роли студент аналогичным образом получает свой токен; один токен соответствует одной роли.
- Все изменения состояния игры, фон и настройки комнаты записывает только ведущий; участник может отправлять и отменять только своё решение, голосовать только от своей роли.
- Комнаты публикуют **только безопасные снимки** данных: до раскрытия решений остальные участники получают отметку о сдаче выбора, но не сам выбор; все голоса доступны ведущему, студенту — лишь собственный.
- Синхронизация работает через опрос Edge Function каждые ~1,3 секунды с оптимизацией по номеру версии. Это не Supabase Realtime WebSocket, а близкая к реальному времени синхронизация с небольшой задержкой.
- Таймеры синхронизируются с серверным временем.
- Комнаты хранятся до 30 дней после создания. Срок действия истёкшей комнаты не продлевается автоматически.

## Использование

1. Преподаватель открывает https://voran1987.github.io/parlamentiya/revolyuciya/ и нажимает **«Создать игру»**.
2. Команды сканируют QR-код или вводят четырёхсимвольный код комнаты на этой же странице.
3. Преподаватель открывает **«Экран проектора»** (это read-only просмотр).
4. Студенты занимают свои роли, выступают, договариваются и тайно отправляют решения.
5. Ведущий раскрывает решения и переводит игру в следующий раунд.

Для восстановления роли или ведущего нужно использовать **тот же браузер, профиль и устройство**; удаление локального хранилища уничтожит токен, доступ автоматически не восстановится. При утере ведущего токена рекомендуется создать новую комнату. Не передавайте секрет ведущего третьим лицам.

## Важные замечания по переносу

- Существующие комнаты Firebase **не импортируются автоматически**. Создавайте новую комнату в Supabase.
- Файлы `firebase-config.js` и правила Firebase других страниц репозитория не изменяются.
- Подключение к Firebase с страницы `revolyuciya` удалено.
- Для полноценного приёмочного теста с несколькими устройствами проверьте создание комнаты, занятость роли, смену выбора, тайное отображение до раскрытия, голосование, переход между раундами, проектор, возврат ведущего и завершение игры.

## Изменение API

Для изменения серверных правил правьте `supabase/functions/revolution-game/index.ts`, а затем разверните новую версию через подключение Supabase или Supabase CLI. Изменение файла только в GitHub **не развернёт Edge Function автоматически**.
